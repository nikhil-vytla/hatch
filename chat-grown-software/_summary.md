Geoffrey Huntley's idea of growing an application by chatting with a live image ([Jiti](https://github.com/ghuntley/jiti), in Common Lisp) is rebuilt in TypeScript on a `node:vm` realm. Functions are late-bound globals, so redefinitions take effect without a build. Every change must pass caller-owned gates before a revision is published. An expense tracker grown over eight chat turns then faced 245 model-style mutants (flipped operators, dropped lines, stray state writes, hangs, drive-by edits to unrelated functions) across seven layers: static, invariants, a ratchet of user-confirmed examples, properties, boundary fuzzing, replay of recorded real use, and per-turn goals. Together the layers caught 96-97% of the mutants that change observable behaviour, rising to 100% once the kernel's coverage report prompted two missing examples, with no legitimate change rejected.

- Machinery that needs nothing from the user (static checks, invariants, fuzzing, use-trace replay) caught about 75%. User-confirmed examples supplied the rest, and every first-round miss was a contract gap: an uncalled function, or an unstated boundary.
- Declaring each request's scope makes use-replay decidable: out-of-scope behaviour changes are rejected, and in-scope ones are shown to the user as a diff.
- A "function" form could carry top-level code that replaced `Array.prototype.every` and silently passed every invariant. The checks must not share mutable machinery with the code they check.
