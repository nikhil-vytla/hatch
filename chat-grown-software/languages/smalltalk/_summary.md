Smalltalk is the original live image, and this Pharo 12 port of the chat-grown-software kernel uses it that way: each accepted function is a method compiled into a live `ExpenseApp` class, so existing callers see a recompiled method on their next send. A Pharo `RBParser` AST gate (allowlisted globals, forbidden reflection and `perform:` sends, one method per form) replaces the usual sandbox, candidates run in a rebuilt scratch class under a terminable 1 s watchdog, and persistence is a per-world saved image plus an atomic `world.json`. It passes all 51 conformance checks (develop about 24 ms, start about 130 ms). The showcase uses Epicea and the `.changes` file for `why` and rollback, and adds an instance variable to migrate the live state holder in place. Built on [Pharo](https://pharo.org) and its Epicea change log.

- Selector convention: the function name is the first keyword, dispatched on (name, arity), so `add_expense: a category: c` answers `add_expense(a, c)`.
- Image save costs 256 ms (55 MB) versus 1.7 ms for the write-ahead `world.json`, so the image is saved only at clean shutdown.
