# ADR-001: immutable synthesis lifecycle with sealed family admission

Status: accepted and implemented on 2026-08-01.

## Context

Parallax already had repository recipes, symbolic task variants, SWE-bench
episodes, canonical identity helpers, and hardened grading. The next slice
needed to prove one complete benchmark path without replacing those APIs or
turning each lifecycle noun into a separate shallow module.

GSM8K is useful for the first proof because a pinned record has a small public
question and a sealed scalar answer authority. Native equivalence is local and
deterministic. Frozen evolving-intent proposals can produce matched and evolved
conversation schedules without provider calls.

The key risks were duplicated identity, future-turn or answer leakage,
regenerated terminal requests, unmatched control budgets, partial family
publication, and replay that silently consulted live inputs.

## Decision

Use one immutable lifecycle:

`SourceTask -> ProposalBundle -> SynthesisPlan -> RenderedTask ->
AdmissionCertificate -> RuntimeSpec -> Verdict`

Organize it by domain knowledge in three modules:

- `gsm8k.py` owns pinned source ingestion and answer equivalence.
- `evolving_intent.py` owns frozen provenance, typed intent events, plans, and
  replay.
- `kernel.py` owns rendering, family admission, locked artifacts, and runtime
  execution.

`SynthesisPlan` is the closed union `StaticPlan | IntentPlan |
CheckpointPlan`. `RuntimeSpec` is the closed union `ConversationRun |
WorkspaceEpisode | CheckpointSequence`. Only `ConversationRun` executes in this
slice.

The compiler copies the exact source question into every terminal anchor. It
never accepts a generated terminal request. Matched and evolved plans share one
budget value and turn count. Matched plans replay only if they equal the
kernel's fixed no-change schedule.

Every arm renders one public and one sealed canonical payload. Public payloads
contain the opening turn and safe pinned metadata. Sealed payloads contain
future turns, proposal provenance, and answer authority. Their digests feed
`ids.task_id_for`.

Admission evaluates the whole family before publication. The certificate names
source and verifier parity, anchor replay, budget equality, leakage, oracle,
wrong-answer, and deterministic rebuild checks. Artifact publication uses a
temporary sibling directory and atomic rename. Lock publication uses a flushed
temporary file and atomic replacement.

Locked replay follows only byte-digested source and proposal references in the
lock. It rebuilds the family and compares every expected artifact digest before
writing.

## Consequences

The caller gets one small API:

```python
family = parallax.build(source=source, strategy=strategy)
verdict = await parallax.run(family.arm("evolved"), agent=model)
```

Identity and grading outcomes stay compatible with the existing code. The
family is a causal unit rather than three independently admitted tasks.
Artifact reruns converge to the same bytes and reject a content-addressed path
that already contains different data.

The lock remains tied to local frozen files. It is not a dataset downloader or
portable bundle. That is intentional for this slice.

Provider adapters, workspace execution, checkpoint execution, broader dataset
ingestion, and migration of prior task models remain outside this decision.

## Cross-domain constraints

The common kernel stops at identity, sealing, proposal provenance, family
admission, runtime linkage, and verdict recording. Domains retain native
submission and verification semantics. GSM8K owns scalar answers, BIRD-SQL
owns database fixtures and execution equivalence, BrowseComp+ owns search
capabilities and evidence, and SWE-bench owns repository provisioning, patch
capture, and the official harness.

Microsoft Evolving Intent is an optional, pinned proposal producer rather than
a Parallax runtime dependency. Parallax may import frozen output and port
typed scheduling semantics with fixture parity, but rendering, admission,
runtime, identity, and reward remain Parallax-owned. Locked builds never call
the upstream code or a provider.

Intent trajectories and checkpoint sequences remain separate plan types.
Intent evolution keeps one conversation and reveals changes to a latent
request. Checkpoint evolution carries a workspace across separately scored
specifications, may start a fresh conversation at each checkpoint, and
accumulates regression obligations. A universal transformation algebra was
rejected until more synthesis families demonstrate shared operations beyond
the artifact lifecycle.

The proof order is GSM8K, BIRD-SQL, BrowseComp+, then migration of the existing
SWE-bench proof into task-ID-driven execution. Checkpoint execution follows
only after those four benchmark domains pass locked replay, leakage, oracle,
negative-control, and native-verifier checks.

## Rejected shapes

One file per lifecycle noun was rejected because it would scatter invariants
and force readers to trace simple state across many wrappers. Extending the
existing repository `Recipe` or SWE-bench episode records was rejected because
their storage and verifier assumptions do not fit a sealed scalar benchmark
without optional-field escape hatches. Runtime proposal generation was
rejected because it breaks locked replay and introduces provider provenance at
the wrong boundary.
