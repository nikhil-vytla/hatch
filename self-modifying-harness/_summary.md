An agent that writes, verifies and hot-installs its own tools was built by combining three recent systems:
- [pi-durable](https://github.com/earendil-works/pi/tree/main/packages/durable) contributes crash-safe commits and in-place extension reload;
- [OptChat](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449) contributes an endless chat, held as a binary tree of summaries with zoom;
- [celld](https://github.com/denoland/celld) contributes the cell model, in which code is loaded by version id and state is keyed by name, so state outlives code.

Each agent-written tool is a QuickJS-sandboxed cell with its own SQLite state. A protected kernel admits a new version only if it passes every check of its ancestors (a ratchet) and its migration works on a copy of live state. Every version records the chat message that asked for it. A scripted three-process demo on the real harness grows a tool, rejects a regression, migrates state, survives a crash inside the agent-written tool, and answers "who asked for this?" by zooming to the user's verbatim words. One command, `./forge`, starts it on any [pi-ai](https://github.com/earendil-works/pi) model or a local OpenAI-compatible server, and runs the offline demo when no key is set.

- Recording pi-durable's call id inside the cell's own SQLite transaction made every agent-written tool exactly-once and replay-safe; without it, a crash after commit left the agent guessing.
- Extension install order is a security boundary: with the kernel installed first, a self-written tool silently replaces a kernel tool on reload.
- OptChat's view only composes with pi-durable if positional tool announcements are folded in after the view rather than dropped. Consecutive views shared 40k, 58k and 73k characters at 4k, 20k and 100k messages. At short histories, a plain sliding window gets more prompt-cache reads.
- A second round put the kernel's two doors behind [gdp-ts](https://github.com/rauchg/gdp-ts) compile-time proofs: only a version that passed the gate can be written, and only a catalog read from the committed document can be installed. It also added compare-and-swap, call-time invariants, action coverage, replay of real calls against declared changes, schema fuzzing and crash-safe migrations, all under strict `tsc` and [anti-slop](https://github.com/dmmulroy/anti-slop) lint (0 errors, 59 tests).
- A third round followed the OptChat author's revised spec: merging by a pair's age from its last message reproduces Taelin's rollback `push` at all 20,001 steps, and batching merges from 128 KB down to 64 KB cuts the view's cache rewrites from about 53 lines per message to 1.6 (98.8% read from cache).
- On a real model (DeepSeek V4.1 Flash), one untuned run grew and upgraded a tool, with the gate rejecting three flawed upgrades for genuine mistakes, and answered provenance correctly; 96 calls cost $0.07, with 81% of input read from DeepSeek's automatic prefix cache.
- The celld version of the cell model, first written without running it, passes 7 of 7 scenarios on celld 0.6.2 after a one-line fix: a running facet keeps its old code after an upgrade until `ctx.facets.abort` restarts it.
