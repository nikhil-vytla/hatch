## Context

Parallax's accepted synthesis-kernel slice proved an immutable GSM8K lifecycle,
but it did not implement Microsoft Evolving Intent generation. The episode
spine proved several runtime paths, but its SWE-bench path remains local,
Lite-based, and weaker than the hardened repository grader. The symbolic
variant, synthetic campaign, repository recipe, GSM8K family, and SWE episode
models still assign state, identity, and evidence independently.

The accepted GSM8K fixture is hand-authored. Its prompt and response digests are
placeholder-shaped strings, and its `school_supply_sales` context does not
match the Natalia's clips source task. Its family identity proves deterministic
artifact bytes, not generation provenance integrity or semantic proposal
validity.

The north star is broader than task synthesis. Parallax must support a complete
research loop:

`observe -> hypothesize -> intervene -> construct -> admit -> run -> compare ->
record -> propose`

Microsoft Evolving Intent, the experiment in arXiv 2607.20734, and SloP Code
Bench expose incompatible state machines:

- Evolving Intent updates a latent function-and-argument state inside one
  interaction and evaluates its terminal anchor.
- SloP carries an agent-authored workspace across separately specified and
  scored checkpoints while resetting conversation and runtime state.
- The 2607.20734 study is an experiment over Evolving Intent artifacts with
  controls, ablations, mitigations, and a preliminary training intervention.

Collapsing these into one transformation algebra would erase the variables the
research protocol must control.

## Decision

Add a small immutable research protocol above separate strategy records.

The protocol owns:

- observations, behavioral-failure predicates, and evidence references;
- mechanism hypotheses and falsifiable research questions;
- interventions, conditions, estimands, assignment, metrics, and stopping;
- policy and environment commitments;
- run and analysis reports;
- decision records and candidate next questions.

Strategy implementations own their native state and transitions. Evolving
Intent and Checkpoint Evolution do not implement a shared transition
interface. They emit strategy-tagged constructed conditions into a common
artifact lifecycle only after their own invariants pass.

Domain adapters own source ingestion and native evaluation. They are supplied
through explicit constructor/catalog injection. There is no closed domain enum,
global registry, import-time discovery, or generic escape hatch.

The shared lifecycle is limited to:

`source pin -> frozen proposal/spec -> identity -> seal -> admit -> run evidence
-> analysis -> decision`

Identity includes all semantic requests, responses, parses, prompts, validators,
model parameters, seeds, environment specifications, and verifier commitments.
Provider request IDs, timestamps, and billing telemetry remain an audit
sidecar and do not change semantic identity.

Run attempts use the closed rejection taxonomy `transport | provider | parse |
schema | semantic | judge`. Parsed blobs survive schema and semantic rejection.

## Experimental claim discipline

The evidence model distinguishes:

- observed behavioral failure;
- hypothesized mechanism;
- intervention;
- measured outcome.

No serializer, analyzer, or controller may infer one category from another. In
particular, zero reward does not imply model incapability, training failure, or
environment failure. Capability checks, valid-submission checks, controls, and
replication must precede attribution.

Every experiment freezes treatment/control construction, parity policy,
randomization or blocking, repetitions, capability gates, negative controls,
contamination checks, metrics, uncertainty method, and stopping/abstention
rules before treatment outcomes are visible.

An RL environment is a first-class commitment over state, observation, action,
transition, reward authority, termination, resets, tools, budgets, and data
split. A benchmark run evaluates a policy. Claims about training additionally
require an identified policy-update intervention and controlled training
experiment.

## Migration

Use a hard deletion-first migration:

1. characterize real upstream and native-verifier paths;
2. preserve baseline receipts, then delete or quarantine the disconnected
   universal variant algebra, production use of synthetic campaign records,
   checkpoint placeholders, and unsupported production claims;
3. add research-protocol and evidence records only after subtraction;
4. replace the quarantined Evolving Intent proposal model with source-grounded
   types;
5. move GSM8K assumptions out of the shared kernel;
6. migrate the bespoke SWE episode only after state and verifier gates pass;
7. add checkpoint evolution as a separate strategy after Evolving Intent's
   controlled experiment slice is green.

There is no multi-release dual path and no compatibility claim for removed
models.

## Verification gate

Unit 0 executed the archived
[`verify-parallax` skill](https://github.com/nikhil-vytla/hatch/tree/cursor/hard-repo-tasks-5fc8/hard-repo-tasks/.cursor/skills/verify-parallax)
through Launch, Doctor, Drive, Evidence, and Cleanup for the family-build
path. It proves the app-level skill baseline, not either source strategy.
Strategy implementation remains forbidden until the remaining gates provide:

- real source-revision characterization receipts;
- an asset feasibility report for GSM8K, BIRD-SQL, BrowseComp+, SWE-bench, and
  SloP;
- structural scheduler parity and deterministic-prefix text parity;
- native oracle, known-wrong, and external-asset tamper checks where assets
  exist;
- a wheel-installed custom-domain constructor contract.

The one app-level skill does not add a production verification CLI. It may use
an independently executable helper to compose direct user commands with
comparison, source manifesting, receipt creation, failed-run retention, and
cleanup. The helper must preserve the direct invocation as the user path. A
separate skill requires different launch or isolation semantics.

Imported upstream JSON is marked imported and source-digested. It may
characterize parity but cannot seal or enter a production family.

## Consequences

Parallax gains one place to define what an experiment can claim without
pretending all task construction is the same. Strategy implementations remain
concrete and small. New domains require explicit construction and real native
verification.

The price is a deliberate pause before more production code. Some requested
paths may remain blocked by licensed corpora, databases, Docker images, or
training access. Those are research constraints to record, not gaps to hide
behind fabricated fixtures.

## Rejected alternatives

- Candidate C's closed domain enum and seam-authored provenance, as recorded in
  [`DESIGN-SELECTION.md`](DESIGN-SELECTION.md).
- Candidate B's multi-release migration and source-only revision event, as
  recorded in [`DESIGN-SELECTION.md`](DESIGN-SELECTION.md).
- A universal transformation algebra spanning intent and checkpoints.
- Runtime generation inside deterministic builds.
- Global registries or automatic domain discovery.
- Prompt-only write isolation for stateful coding tasks.
- Post-hoc analyses selected after treatment outcomes.
- Treating LLM-judge output as native truth without identity-bearing call
  evidence.
