Is TypeScript the right language for a kernel that grows software by chat, as Geoffrey Huntley's Lisp-based [Jiti](https://github.com/ghuntley/jiti) does? To find out, five kernels (Clojure, Elixir/BEAM, Pharo Smalltalk, Racket, Lean 4) were built in parallel next to the JavaScript original, all speaking one JSON-lines protocol. In each, [DeepSeek](https://api-docs.deepseek.com/) grew an expense tracker and an LLM API gateway while a simulated user confirmed every answer and hidden checks scored the result, 3 runs per language. Correctness barely depended on the language: JS, Clojure, Elixir and Smalltalk scored 98-100% and Racket 95-100%. Lean scored 83-91% at 3-12x the output tokens, because it must also prove its laws. What the languages change is what the kernel can know and do safely, shown in seven recorded videos.

- Code-as-data kernels (Clojure, Racket, Smalltalk, Elixir, Lean) refuse calls to missing functions and top-level side effects statically. JavaScript only notices when a test runs the code.
- Elixir hot-deployed quotas and a data migration into a live gateway: 564 requests from 5 clients, 0 unexpected failures.
- Racket's sandbox contained attacks that escape `node:vm`. Two of eight prompt-injected changes still passed every gate: rounding pricing in the attacker's favour, and leaking keys in error text.
- Lean's proved quota law refused three bugs that each passed 19/19 examples and 300/300 random tests.
- The simulated user first "confirmed" answers that broke its own invariants, and an 8000-token output cap cost Lean whole turns. Both were fixed and every run repeated.
