# Disclosed single-hunk normalization, version1

Frozen2026-09-21 after the retained strict-validation failure and before any new live request under this condition. The original model response repeatedly contained a useful source change with an incorrect unified-diff line count. The original failure and its test result remain immutable evidence; this change does not relabel that run a success.

The executor first parses the typed artifact and runs strict hunk validation. If validation fails, it may recalculate counts only for one complete LF text file with one hunk, ordinary a/b file headers, optional standard diff/index prelude, valid line prefixes, nonnegative safe-integer offsets, and at least one changed line. Missing trailing newline, additional hunks/files, CRLF repairs, malformed structure, invalid zero offsets and ambiguous file-header lines remain errors. Already valid patches are returned unchanged.

Normalization changes only the old/new count fields in the existing hunk header. It does not change paths, start positions, context, deleted lines or inserted lines. The returned proposed artifact includes the complete original text, original malformed status, old/new header, header line number and explicit syntax-only validation scope. The browser displays the repair disclosure. MCP and SDK callers receive the same metadata. The router never applies the proposal.

Acceptance requires independent host `git apply --check`, application without recount, and task tests. Tests also require an original wrong-count patch to fail strict application, the normalized proposal to pass and fix the fixture, and a mismatched-source patch to remain inapplicable. The source hashes in the root's scripted live record identify the exact implementation used. A fresh live request after this change is a distinct artifact-processing condition, not a reroll of the unchanged strict condition. Task-quality attribution must distinguish a model's original artifact from the repaired proposal.
