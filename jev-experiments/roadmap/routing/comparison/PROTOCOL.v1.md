# Bounded routing comparison v1

Frozen on 2026-09-20 before destination outcomes. Eight newly authored synthetic coding tasks use four calibration and four held-out IDs in tasks.json. These are engineering fixtures, not representative tasks or benchmark scores. The task author wrote deterministic answer graders before inference. Task context includes all needed data; no model executes tools. Each destination is called once per task, serially, with a 1024-token output allowance and strict artifact JSON schema. Errors and malformed outputs count as failure; no rerolls.

Destinations are the two dated gateway entries in ../web-registry.ts. Calibration chooses one aggregate success probability per destination with Laplace smoothing, (passed+1)/(n+2), plus measured median latency. The same aggregate score populates each category's easy and hard endpoints because four calibration rows cannot support a category-by-difficulty fit. That intentionally limits classifier-dependent ranking in this tiny study; outcome differences may be zero. A later adequately powered study must fit a richer mapping using calibration data only. Token pricing uses the recorded gateway list-price configuration; it is arithmetic on reported usage, not an invoice or measured savings.

The frozen selection policy uses quality/cost/latency weights 0.6/0.25/0.15, no tools, no fallback, no verifier, one attempt. Compare fixed model A and B to four classification conditions: lexical heuristic; host agent traits recorded before seeing destination answers; hosted Jev typed questions; local frozen Laya typed questions. Classification uses ../classifier.ts. All conditions use the same calibrated registry and policy. Record classifier duration and known/unknown cost separately. Include overhead in replay total latency and cost, preserving null when any component is unknown.

Held-out evaluation replays each selected destination's actual measured result. Reuse is explicit: it generates no new answer and is not a live router trial. Primary metric is deterministic grader success over all four held-out cases. Also report selection coverage, classification category accuracy/Brier score when a full distribution exists, difficulty agreement to author annotations, and observed request failures. Display per-task choices and overhead, not a superiority claim. Verifier overhead is exactly absent because verification is disabled, not measured as a free service.

Local classification runs only after the training agent releases GPU ownership. A blocked local condition remains missing and cannot be silently replaced with heuristics. Keep any failed run, changed protocol, or unavailable provider alongside the result.
