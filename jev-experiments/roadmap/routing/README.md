# Model Routing Lab

This folder contains the shared TypeScript router, Bun CLI, local MCP server, web preview and recorded evidence. The router delegates a bounded task and returns an answer, structured result or proposed patch. It never applies edits or gives a destination tool access. The calling coding client reviews the result, applies changes under its own permissions and runs independent tests.

## Run it

Install from this checkout with `sh jev-experiments/roadmap/routing/install.sh`, or pass an explicit prefix as its first argument. This builds a small Bun script bundle without training dependencies, weights or client configuration changes. Add the printed bin directory to PATH. Uninstall by removing only that prefix. A historical version 1 [fresh temporary-prefix install](fresh-install.json) passed doctor, stdio discovery and a read-only email example.

From the repository root:

```sh
bun jev-experiments/roadmap/routing/cli.ts doctor
bun jev-experiments/roadmap/routing/cli.ts decide request.json
bun jev-experiments/roadmap/routing/cli.ts classify_eml message.eml
JEV_ROUTER_CONFIG=jev-experiments/roadmap/integration/examples/router.json \
  bun jev-experiments/roadmap/routing/cli.ts route_task \
  jev-experiments/roadmap/integration/examples/task.json
bun jev-experiments/roadmap/routing/mcp.ts
bun test jev-experiments/roadmap/routing
```

No destination is configured by default. `doctor` reports the configuration. The example route requires an installed, authenticated OpenCode and access to the specified Bedrock model. A trusted JSON registry supplies capabilities, model limits, pricing evidence, destination endpoint and policy. Remote HTTP destinations require HTTPS; local destinations require loopback and reject redirects. The server writes only JSON-RPC on stdout. Optional `JEV_MCP_AUDIT` records method names, status, artifact kind and context byte counts, never task text or credentials.

`route_task` uses the lexical heuristic unless trusted configuration explicitly selects a classifier. Use `"classifier": {"kind": "hosted-jev", "apiKeyEnv": "AI_GATEWAY_API_KEY"}` for hosted Jev, or `"classifier": {"kind": "local"}` with an explicit `localRuntime` for that installed model. `"classifier": {"kind": "heuristic"}` names the default. Configuring `localRuntime` or `decisionEndpoint` alone affects `decide` and does not opt routing into a model. `doctor`, MCP initialization and each result disclose the classifier.

Both opt-in classifiers use the same category/difficulty questions and selector policy. Difficulty is the ordinal expectation. Hosted classification makes at most one outbound attempt; local classification has no cloud fallback. Failed, unsupported or cancelled classification makes no destination attempt. Local adapter/revision identity and typed refusal messages/question IDs survive the result projection. Unknown costs stay unknown. These classifiers do not declare an enforceable maximum charge, so a hard spending cap refuses them before invocation; local-only policy also refuses hosted classification.

The TypeScript `route_task` alias and `routeConfiguredTask` honor this configuration. Lower-level `routeTask` accepts caller-owned classifier/executor/verifier hooks. [Current archived verification](../../typed-runtime-2026-09-22/README.md) includes actual CLI/MCP processes driven by authored responses. These fixtures test configuration and behavior, not routing quality or model savings.

`decide` uses version 2 of the shared [typed decision contract](../runtime/contract.ts). Version 1 requests are rejected explicitly. With no adapter or endpoint configured, it deliberately returns a labeled state-blind uniform prior. `classify_eml` is an explicit local lexical baseline for unencoded text/plain messages under 100 KB. It returns uncalibrated normalized rule weights and rejects MIME formats it cannot parse. The [Mac runtime](../mac/README.md) runs checksum-verified experimental models and supports decoded MIME. To use it from the same CLI/MCP operations, set `localRuntime` using the [explicit local configuration](../integration/examples/local-runtime.json), with your installed executable, data directory and model ID. The Mac toolkit uses the pinned experimental readout by default, while this bridge requires an explicit model ID. The unconfigured Bun CLI retains its labeled baselines. Historical MCP-to-MLX [base](local-mcp-base.json) and [adapted readout](local-mcp-readout.json) records use version 1 and are not current-source inference evidence. The older `local_mcp_smoke.py`, `comparison/local_classify.py` and Mac `verify_readout_runtime.py` are retained historical runners. Run them only against their recorded source revision. This slice checks the new wire format with authored responses and does not establish local-model email usefulness.

The SDK exports `decide`, `route_task`, `classify_eml`, `selectRoute`, `createDecisionClassifier` and `createHostClassifier`. A hosted Jev or local adapter can feed the same typed category/difficulty questions through `createDecisionClassifier`. `routeTask` receives that classifier plus declared locality and maximum charge metadata. The selector is unchanged across conditions. Optional category-specific easy/hard quality values interpolate at the classifier's difficulty for ranking. The hard `minimumQuality` floor always uses aggregate measured `route.quality`, so classifier predictions cannot make an otherwise ineligible destination qualify.

## What is enforced

Capability, tool permission, route allowlist, locality, full input/output coverage, measured minimum quality and spending bounds are checked before ranking. Empty eligibility returns reasons. No branch widens it. Prices and cache state carry evidence labels. A hard cap requires configured prices and uses a full cold input/output reservation, even when the display simulates cache savings. Unknown charges retain their full reservation for subsequent attempts; total unknown cost remains null. OpenCode cannot provide an enforceable per-call charge bound and is excluded when a cap is present.

Availability fallback needs explicit configuration and keeps the restrictions. Quality escalation requires a valid verifier rejection and an eligible route with higher measured quality in both aggregate and task-calibrated scores. When task calibration is absent, the task score uses aggregate quality. A local-only task requires an explicitly declared local verifier identity before verification can run. Verification is also skipped under a hard budget until a verifier maximum charge is available; the returned proposal is marked unverified. Invalid or thrown verifier responses return an error without escalation, retain any readable verifier evidence and the original attempt, and leave unknown charges null. Cancelled or rejected proposals do not remain in the final outcome.

SDK classifier, executor and verifier callbacks run in the caller's process and are trusted implementations, not a sandbox. Locality declarations cannot prevent a dishonest callback from making network calls. The router checks declarations before invocation and validates returned metadata; contradictory reported classifier identity is retained separately from the declaration and stops destination execution. Runtime accounting rejects negative, nonfinite or malformed values. Direct selector calls cannot widen a policy's spending cap through remainingBudget, and malformed registry entries stay ineligible.

HTTP execution requests a strict `kind`/`text` JSON schema. Patch hunk arithmetic is checked after parsing. A [narrow, disclosed normalization](HUNK-NORMALIZATION.md) can recalculate only the count fields of one otherwise complete single-file hunk; it retains the original malformed text and marks the proposal with repair metadata. Other malformed returned text is preserved for inspection. Neither syntax validation nor normalization proves that a patch applies or fixes the task: the host must independently check, apply and test every proposal. OpenCode requires destination.model to equal route.model before execution. Its identity remains configured-unverified because the event stream does not independently report the answering model. HTTP and custom executor responses that explicitly name a different model return an error, retain the reported identity and valid usage, and leave the charge unknown. No model aliases are inferred, and a contradictory artifact cannot trigger fallback or verification. These post-response checks cannot undo provider work already performed.

The final parser correction recognizes deleted SQL/Lua `-- ` comments as hunk content and requires complete header pairs for each file. The frozen normalization protocol and `single-hunk-counts-v1` repair kind remain unchanged: only the two count fields may change, and path-shaped ambiguous header lines still cannot be normalized. This fixes input recognition without changing the repair or its disclosure. Historical live records identify their earlier source snapshot and have not been rerun or relabeled.

## Evidence and limits

The [integration report](../integration/README.md) contains actual OpenCode, Claude Code and Codex MCP calls, host-applied changes and independent tests. The [recorded example](recorded-example.json) is an actual Fable 5.1 Global configured delegation that proposed a loop fix. Its cost is unknown. The [bounded comparison protocol](comparison/PROTOCOL.md) freezes four calibration and four held-out synthetic tasks and an independent grader. Replayed routing results reuse actual destination responses and are labeled offline policy comparisons. They cannot establish superiority, general coding capability or production savings.

The web preview separates recorded evidence, simulated quality/latency/cache values, and BYOK execution. The first live response failed typed parsing. A protocol change added a strict JSON schema; a subsequent patch had wrong hunk counts and required a disclosed host repair. Both original attempts remain as [malformed output](../verification/live-route-first-malformed.json) and [historical host repair](../verification/live-route-historical-host-repair.json). A later [strict rejection](../verification/live-route-strict-failure.json) motivated the disclosed count-only normalizer; the original remains a failure. The current [scripted live check](../verification/live-route.json) retained another wrong-count model proposal, disclosed the toolkit normalization, then passed strict host application and five inclusive-sum assertions. That is one successful task after a recorded syntax repair, not a claim that the original model artifact was valid. No rerolled output replaces the original observations.

The historical version 1 source passed 66 provider-free routing/artifact/MCP checks (398 assertions) passed when that report was written. Those counts do not verify the current version 2 source. They include actual stdio discovery, no-route/unsupported responses, cancellation, null request recovery, eligibility bounds, reservations, malformed artifacts, classifier identity consistency, verifier locality and malformed hook accounting. Separate actual-client interruption and malformed-output evidence is linked in the integration report. CLI and web use one HTTP executor; provider usage validation and artifact parsing are shared. The current source-built installer smoke produced an 84,933-byte bundle and passed doctor, three-tool discovery, unchanged-file lexical classification and uninstall; its checksum is retained in fresh-install.json. The public lab offers direct asset downloads for protocols, comparison results and each primary client run’s summary, MCP audit, host transcript, applied diff and independent tests.
