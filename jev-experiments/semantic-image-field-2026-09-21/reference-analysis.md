No LICENSE file or license declaration appears in the inspected Space tree, README metadata or package manifest. The upstream Transformers.js examples repository has an [Apache-2.0 license](https://github.com/huggingface/transformers.js-examples/blob/main/LICENSE), which does not by itself establish permission for every addition in this Space. Implement an original layout from the interaction ideas rather than copying its source. Photograph rights remain with the Unsplash contributors; those assets are separate from our museum collection.

Despite its “Multimodal Jev” subtitle, the actual [worker](https://huggingface.co/spaces/webml-community/semantic-image-field/blob/5d25812bb2d3e5174c5b05beeb227cdf5205c362/src/worker.js) uses **CLIP**, not the Jev API. Transformers.js 4.3.0 loads `Xenova/clip-vit-base-patch16` with q8 weights, WASM and one thread. The [conversion model card](https://huggingface.co/Xenova/clip-vit-base-patch16) identifies OpenAI's CLIP ViT-B/16 as its base. Text embeddings are compared with precomputed image embeddings; the browser does not freshly encode each displayed photograph.

The README describes 24,989 images and 512-dimensional float32 vectors, roughly 49 MiB before model downloads. [Asset URLs](https://huggingface.co/spaces/webml-community/semantic-image-field/blob/5d25812bb2d3e5174c5b05beeb227cdf5205c362/src/assets.js) use the dataset's moving `main` revision, and model loading specifies no revision. Pinning the Space therefore does not pin its complete runtime inputs. Search text stays in the worker, while model, database and photo downloads still contact external hosts. This is not an offline archive. The tokenizer enables truncation; long-query coverage was not tested.

## What the spatial interaction actually does

[Layout code](https://huggingface.co/spaces/webml-community/semantic-image-field/blob/5d25812bb2d3e5174c5b05beeb227cdf5205c362/src/layout.js) starts with a deterministic scattered arrangement. A query changes it to a golden-angle spiral: stronger ranks move inward, with modest size variation and clearance around the central search box. Coordinates are calculated from rank, not a two-dimensional projection of image embeddings. Nearby photographs are not necessarily visually similar to each other.

The [field](https://huggingface.co/spaces/webml-community/semantic-image-field/blob/5d25812bb2d3e5174c5b05beeb227cdf5205c362/src/ImageField.jsx) maintains 96 images, or 56 below 650 pixels wide. The worker returns 60 matches; remaining places retain existing images where possible. DOM identity persists across rearrangements, incoming images enter from edges, and image loading does not delay movement. One animation clock drives motion and pointer parallax; reduced motion removes displacement effects. Only the first 12 results enter the tab order.

[Relevance styling](https://huggingface.co/spaces/webml-community/semantic-image-field/blob/5d25812bb2d3e5174c5b05beeb227cdf5205c362/src/relevance.js) maps current cosine scores through a query-relative sigmoid into opacity and blur. Its top six scores saturate toward full visibility, with a minimum score spread to limit exaggeration of near ties. This is visual emphasis, not a probability or a calibrated cutoff. The [app](https://huggingface.co/spaces/webml-community/semantic-image-field/blob/5d25812bb2d3e5174c5b05beeb227cdf5205c362/src/App.jsx) coalesces queued queries and accepts results only for the current request ID. Clearing invalidates old answers even if already-running inference finishes.

## Feasible original improvements for the artwork browser

Our [current 204-artwork browser](../experience-prototypes/src/visual-search.tsx) compares lexical matches, Jev metadata ranking and Jev caption-assisted ranking. Jev sees museum text, not image pixels. Keep those modes, existing evidence and public-domain artwork sources intact.

- Add a bounded **field view** beside the complete grid. Move strong matches toward a clear central region, preserve artwork identity between methods, and keep titles and source details one action away. Start with a smaller visible population, then profile before increasing it.
- Use rank bands with restrained emphasis. Equal scores should receive equal relevance treatment; artwork ID can resolve placement without implying a quality difference. Missing responses remain visibly unscored, distinct from low relevance. Do not transfer CLIP cosine normalization onto Jev's expected 0–4 rubric scores.
- Keep instant lexical browsing and recorded presets. Live Jev ranking remains an explicit action; typing must not trigger a paid full-collection run. Preserve request invalidation on edits, reset, cancellation and unmount. Label pending results with their evaluated query rather than displaying them as answers to new text.
- Preserve a complete keyboard-accessible grid/list, stable focus, touch targets, dialog focus return and reduced-motion behavior. Add stable aspect-ratio placeholders and prioritize visible thumbnails while retaining museum links when previews fail.
- Export the existing complete ranking plus view settings and layout seed. Validate that changing presentation never changes scores, ties, coverage or exported artwork IDs. Test rapid query/method changes, image failures, keyboard/mobile use and frame times independently of ranking quality.

A later CLIP comparison would be a separate model condition: encode these same 204 artworks with a pinned matching image encoder, checksum the aligned vectors and metadata, and evaluate against independent relevance judgments. The reference's motion alone does not establish improved retrieval, image understanding or faster Jev inference.
