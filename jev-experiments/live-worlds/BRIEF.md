# Agreed prototype contract

Build real, continuously running experiences. A request must never pause gravity, movement or other entities. Rendering and simulation clocks are independent of async model work. Human takeover preserves current state. Visible game ends, restarts and progression belong to the full game; a fixed benchmark horizon does not limit play.

Compare two branches from an identical checkpoint, at a synchronized world clock. Each can run assisted or unassisted. Show accepted model decisions, stale/failed replies and time under fallback separately. Code actuating a chosen target is distinct from a fallback choosing a new target. Store decisions and snapshots; scrub replays without fresh requests. Branching preserves old runs and invalidates pending work. Restorable snapshots include simulation time, RNG state/scheduled disturbances, current actor states and relevant memory. Request validity depends on branch/epoch, semantic revision and action preconditions, not whole-world equality while physics moves.

Expose useful differences in framing: raw short actions, lasting destinations or simulated outcomes, and general semantic intent mapped to available policies where appropriate. Do not claim a wording-only comparison when information, search or code assistance differs. Good deterministic baselines are valuable and must be clearly named. Model-selected metadata does not establish direct vision, audio understanding, calibrated confidence or realistic human prediction.

Use current app colors, dark mode, accessible controls, reduced motion and mobile layout. Make the world visually legible and enjoyable first; put technical evidence in a collapsible inspector. Browser BYOK uses src/api.ts run/getApiKey only, memory-held key, no owner fallback. No new quotas, approvals or key storage. Saved demo evidence can use authorized local recorder credentials; never expose them in bundles/logs. The large JudgeBench recording is still running, so avoid broad new paid-model batches without coordination.

Each owner supplies meaningful engine/lifecycle tests, browser interaction verification, README/NOTES/_summary for owned folder, and concise integration instructions. Original new code only; do not vendor fetched repositories or commit generated dependency copies. Root handles main.tsx/catalog/publication/prepare/package integration. Use Bun. No commits or deployment by workers.
