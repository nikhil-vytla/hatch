# Decision runtime and training capability audit

The shared interface currently narrows Jev. It preserves JSON state and complete decision distributions, but cannot express the documented structured question language. Some limits are explicit and useful; others silently discard fields or change the requested primitive. Resolve this at the foundations layer before describing adapters as interchangeable native Jev implementations. This audit changes no runtime, trained model, frozen protocol or published result.

## Native reference and scope

TypeSafe's [advanced primitive documentation](https://docs.typesafe.ai/primitives/advanced) defines `EntryType` as string, object, array or null in instructions, Choice descriptions, Score levels and Noul true/false criteria. Passing structured state is a separate capability from preserving these question fields. [Choice](https://docs.typesafe.ai/primitives/choice) exposes a selected option, the full distribution and distribution-derived confidence; it permits up to 255 options. [Score](https://docs.typesafe.ai/primitives/score) uses ordered descriptions, exposes probabilities and a legend, and returns their index-weighted mean, which may lie between levels; its documented maximum is ten levels. [Noul](https://docs.typesafe.ai/primitives/noul) is the probability of yes, with optional true/false descriptions. Its scalar already specifies the two-outcome distribution; it is not a measurement of degree.

These are native documentation facts checked on 2026-09-22, not a fresh compatibility test of Vercel's particular hosted route. No provider or local model was invoked. Code inspection and authored transport fixtures establish the wrapper behavior below. A future migration must separately verify the deployed endpoint's accepted request shapes and actual model identity.

## Consequential findings

**R1. native structure is blocked, while unrecognized semantics can be silently lost.** Both hosted validators reject object instructions, structured Choice descriptions, structured Score levels, null entries and Noul criteria. This is observable rejection, not accidental flattening. Separately, shared `validateRequest` and Mac `validate` accept a valid v1 question with an additional `criteria` object. The hosted adapter then omits Boolean criteria and replaces ordinal criteria with numeric labels; the local helper uses generic descriptions. A caller receives an answer to a weaker question without an unsupported issue. Static TypeScript types do not protect CLI/MCP/HTTP JSON callers. Reject unrecognized semantic fields immediately; a versioned extension should preserve supported native fields explicitly.

**R2. ordinal selection and native Score are different outputs.** In the fixture, probabilities `[0.1, 0.2, 0.7]` correspond to native Score `1.6`. A shared range `[10, 20, 30]` returns `selected: 30`; its mapped expectation is `26`. All probabilities survive, so the mean can be recovered. The response nevertheless provides neither the mean nor a label distinguishing it from argmax. Code that reads only `selected` loses the continuous score and uncertainty. Preserve primitive-specific summaries and the distribution; name an argmax explicitly rather than substituting it for a Score. Keep Noul probability separate from a policy's Boolean threshold. A derived confidence statistic should identify its definition, not be presented as calibrated correctness.

**R3. one option limit incorrectly treats Score like Choice.** `gateway.validate`, `core.Question.check_criteria` and the shared hosted limits accept 11 through 255 ordinal levels; the current native reference says Score supports at most ten. Provider-free probes confirm acceptance of eleven; no provider rejection was induced. Specify per-kind bounds and validate them before dispatch. Keep the Mac eight-option bound independent of the native limits.

**R4. a schema can request Score but receive Noul.** `adapters/typescript/index.ts:compile` checks a numeric 0..1 range before `x-jev-levels`. A number with levels `['routine', 'severe']` becomes `{type:'noul', instructions:'Severity?'}` and loses the level descriptions. The probe reproduces this. Explicit primitive/rubric metadata should take precedence over numeric-range inference. Also validate the shape and maximum length of `x-jev-levels` at compilation: the current Score branch checks neither. Python's missing Score compiler is an explicit capability gap, not evidence that Jev lacks Score.

**R5. completed evidence does not establish structured-question parity.** The newer [corpus preparation](../roadmap/training/prepare.py), `make_corpus`, preserves Typed Decisions Noul criteria by appending their JSON text to the prompt, and Score rubrics by appending a `Scale:` JSON string. Choice descriptions become plain labels. The [backbone compiler](../roadmap/training/study.py), `Backbone.compile`, uses local text packing or a chat template. This is a reproducible transformed representation, not native EntryType pass-through. The earlier [Apple packer](../local-models-and-games/apple/data.py), `pack`, already accepts string true/false criteria and descriptive Score levels, capabilities the newer generic question shape cannot represent directly. None of these local paths establishes object/array/null rubric support: interpolation, concatenation or stringification is not native semantic equivalence.

The earlier [hosted comparison recorder](../local-models-and-games/apple/record_jev.ts) also serializes a per-question state/instruction object into an instruction string and folds Noul criteria into prose. The [first-token reader](../local-models-and-games/apple/prefill.py), `PrefillDecision.compile`, and [full-option reader](../local-models-and-games/apple/sequence.py), `SequenceDecision.predict`, operate on text criteria and run cached branches sequentially. Their distributions are model readouts, not evidence of native parallel execution or native structured understanding.

## Training mechanisms and what their distributions do

The machine-readable [training audit](training-audit.json) covers all five Training & local catalog IDs and the different execution modes within them. The web [Learning component](../experience-prototypes/src/benchmarks.tsx) displays recorded learning curves, candidate prompts and examples; it does not start training or run those models in the browser. The [local-models page](../experience-prototypes/src/local-models.tsx) separates the completed new readout study from the earlier workflow specialist.

| Catalog ID | Actual learning mechanism | Distribution use and remaining depth |
| --- | --- | --- |
| `optimize` | Fixed, random mutation, hill climb, OPRO and real GEPA optimize a string instruction for ten-label BANKING77 classification. No Jev weight updates. | Records Choice probabilities and confidence, but fitness is exact-label accuracy. Only the instruction component changes; candidate descriptions remain fixed. Extend this existing experiment with a separately frozen structured-rubric condition and distribution-sensitive metric, not by rewriting its original run. |
| `teach` | Jev supplies drink labels; TF-IDF logistic regression fits hard selected labels. Random and student-uncertainty acquisition share an attempted budget. | Teacher answer distributions are recorded but not used as soft training targets. Acquisition uses student `1-max(p)`, not teacher uncertainty. Compare soft-label distillation and deferred ambiguous labels on a new held-out fixture set. |
| `reward` | Noul rates every request/menu-item pair; exact expected-reward gradients update a linear policy. | Continuous Noul probabilities are used directly as rewards. This is full-information contextual-bandit optimization, not sampled RL or language-model RLHF. Test separate criterion questions and a fixed aggregation rule against independent task labels before changing the reward definition. |
| `replica` | SmolLM2-360M with LoRA in upper attention layers and learned option/query projections, trained on derived BANKING77 labels. | Choice, Noul and Score vectors train with cross-entropy and are evaluated with accuracy/Brier. Three Score levels exist, but gold labels cover endpoints only. Saved inference returns option choice and probabilities for every question; it does not expose native Score means or Noul fields. Test intermediate-level labels and calibrated primitive-specific outputs before claiming that parity. |
| `local-models` | New three-backbone frozen-readout study, plus clearly separate earlier Laya specialist and untuned readouts. | Full soft targets drive readout loss; evaluation includes NLL/Brier, expected-value ordinal error, coverage and order sensitivity. These are substantial distribution uses. Structured representation remains untested; current transforms, results and installed default should stay immutable when adding a new condition. |

The recorded optimizer test accuracy is 0.86 for unchanged/random/hill-climb/GEPA and 0.84 for OPRO, on 50 held-out cases. Active sampling ends at 0.525 versus random's 0.5375 on 80 authored test cases. The reward run reaches 0.6375 independent test accuracy using 44 successfully annotated training cases. The replica's 77-case Choice accuracy improves from 0.325 to 0.662 while Noul remains 0.403; Score endpoint accuracy becomes 0.455. These values were reconstructed from committed record files, not rerun. They support mechanism inspection, not superiority or general-purpose claims.

## Proposed foundations gate

Use a lossless native question representation in the hosted path, with declared adapter capabilities for instruction/criterion shapes, Score levels, question count and token limits. Keep local contracts as explicit supported subsets. If a text conversion is requested, identify the conversion and retain the original question; unsupported shapes must otherwise return `unsupported` before inference. Do not silently stringify native objects merely to satisfy old string types.

Add round-trip fixtures for nested instruction objects, arrays/null, Choice subtrees, Noul true/false definitions, and descriptive two- and ten-level Scores. Include an eleven-level rejection, Boolean probability distinct from threshold, Score mean distinct from argmax, and unsupported local shapes. Verify exact wire payloads and full outputs before a small authorized hosted compatibility check. Then freeze any new structured-versus-text training/evaluation condition with matched semantic content, validation-only selection, coverage and task success. Existing study and package evidence remain historical and unchanged.

bun jev-experiments/capability-atlas-2026-09-22/runtime-probes.ts

Eight hosted validation cases per language cover a plain control, structured fields, nulls and eleven levels. Additional probes retain silent criteria loss, the actual authored outbound payload, mean-versus-argmax behavior and the two-level schema compilation. The results describe the audited source snapshot; rerunning after a fix should change them.
