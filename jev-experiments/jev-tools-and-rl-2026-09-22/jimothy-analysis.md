# Jimothy: a browser specialist for repeated decisions

Source review completed 2026-09-22. **Recommendation:** investigate a small, fixed-task email classifier that can explain when it should defer. Extend the existing email/runtime work in the next wave; leave the completed typed-decision study and installed default unchanged. The [decision ticket](decisions/jimothy-experiment.md) separates the proposed protocol from verified upstream facts.

Its [package](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/package.json) declares version 0.1.2, Node ≥22 and Transformers.js 4.3.0. The included email bundle [records encoder revision](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/examples/email-browser/model/encoder/encoder-source.json) `751bff37182d3f1213fa05d7196b954e230abad9`; its [model card](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/examples/email-browser/model/encoder/README.md) declares Apache-2.0. New preparations resolve a current encoder revision, so reproducing this bundle requires its explicit pin. The code license does not replace model or dataset licensing.

## What the code does

The [trainer](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/src/train.ts) fits a linear softmax head over frozen MiniLM embeddings or training-fitted TF-IDF features. It accepts saved labels/distributions or obtains teacher labels through a separate API path. This is supervised head fitting, including distillation when teacher distributions supply the targets. It does not fine-tune MiniLM or optimize prompts. The [head implementation](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/src/linear.ts) uses deterministic full-batch Adam.

Each bundle represents **one fixed question**. The [schema](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/src/schema-core.ts) supports choice, boolean, `noul` and score; choice has 2–255 labels and score has 2–10 ordered levels. [Dataset validation](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/src/data.ts) rejects changing task instructions or criteria within a dataset. Inference receives state, not a fresh task definition. It therefore needs a task-hash adapter for our dynamic [typed-decision contract](../roadmap/runtime/contract.ts), with unsupported responses for unmatched questions.

[Automatic training](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/docs/automatic-training.md) separates tuning, temperature calibration and threshold selection. It searches five regularization strengths, then selects an advisory maximum-probability cutoff using a fixed grid and corrected binomial lower bounds. The SDK still returns every prediction; the application decides whether to accept one. Calibration fits winning reference labels, so calibrated probabilities need not reproduce a teacher's uncertainty. Human correctness and teacher agreement must remain distinct.

The [browser SDK](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/docs/browser-sdk.md) runs in a worker: TF-IDF uses JavaScript; MiniLM defaults to q8 WASM. It checks bundle hashes, rejects overlong inputs, queues inference and supports disposal. Loading can be aborted; later predictions are cancelled by disposing the worker. Local WASM fallback from an optional FP16 WebGPU configuration is disclosed in metadata. This is not cloud fallback. Offline persistence still needs application caching, and published verification covers desktop Chromium; Safari, Firefox and mobile remain unverified upstream.

## Evidence and demo limits

The [published email study](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/docs/email-classifier.md) uses 300 synthetic emails generated by GPT-5 nano and labeled by Jev. Its 195/45/60 train/development/test split yields 45/60 teacher agreement in batches and 47/60 in singleton calls. Five predictions change between modes; the maximum probability change is 0.278. No test example has the teacher's `social` label. Ten calibration examples are insufficient, so the threshold is null. These are reported upstream measurements, not results reproduced here or evidence of dependable mailbox automation.

The [live website](https://jimothy-r63s.vercel.app/) was inspected through read-only HTML and JavaScript retrieval. It presents local, Jev and comparison actions; model loading starts automatically in a browser. No browser model load or inference was run in this review. Its retrieved `app.js` exactly matched the pinned [demo source](https://github.com/AndrewPrifer/jimothy/blob/f2ad9b40b88ea913d38fda758e564eac5f12fc0b/examples/email-browser/app.js), SHA-256 `3b244d7d9378e09c46f3e0938f814e21f2568c645bdd44f391fc23e8bd86b252`. This establishes script identity, not the identity or health of every deployed asset. Local timing excludes loading; Jev timing includes the server/API round trip. Those numbers do not establish a full-session speed or cost ratio.

## Where it belongs in Jev

Our [Mac email example](../roadmap/mac/README.md) already classifies explicit `.eml` files, but its 7/12 authored smoke result is weak and its probabilities are uncalibrated for email. Jimothy adds a useful question: can a much smaller **task-specific** browser classifier provide enough validated coverage to justify deployment? Use the existing five email purpose labels, independent human references, an explicit review policy and per-runtime calibration. Do not compare its six-category teacher agreement directly with our five-category smoke accuracy.

This is distinct from [GEPA prompt adaptation](../roadmap-additions-2026-09-21/decisions/gepa-domain-adaptation.md) and the [completed multi-dataset readout study](../roadmap/training/README.md). Reuse their provenance and decision artifacts, not their final tests for new selection. Any savings claim must include label generation, fitting, downloads, runtime startup, unanswered cases and user-authorized hosted calls. A classifier that never earns a usable cutoff is a valid research result.
