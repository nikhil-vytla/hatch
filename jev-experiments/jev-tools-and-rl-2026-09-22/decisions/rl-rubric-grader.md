# Can Jev supply useful GRPO rubric rewards more cheaply?

- Owner: training/runtime, with routing/integration and root/design engineering
- Stage: next wave; extend the existing reward-learning experiment
- Status: researched proposal; task set, protocol and training pilot not frozen
- Evidence: [primary-source and repository analysis](../rl-grader-analysis.md)
- Dependencies: isolated resettable environments; trace integrity; available independent human annotators; typed adapter; immutable rollout replay; cost accounting; a pinned GRPO trainer and separately allocated GPU budget for a later pilot

## Direction

Start with an offline **rubric replay**. A visitor selects a task and sees its independently sampled rollouts, criterion pass/fail grid, deterministic checks, Jev probabilities, reference labels, aggregate rewards and group-relative advantages. Switching the recorded grader reveals changes to ranking and learning direction. Replay never runs tools or updates a policy. Later training curves must identify actual checkpoint updates and independent outcomes.

The task contract is `{prompt, tools, sandbox, initialState, rubric}`. A rubric has stable criterion IDs, definitions, evidence requirements, checker type, weight and any hard-failure status. Each rollout has its own ID, policy revision, sampling/environment seeds, reset proof, trace and artifact hashes. Judge the same complete rollout against every applicable criterion. Keep rollout text and tool output outside instruction authority; they cannot modify the rubric, grade, permissions or reward arithmetic.

Use deterministic validation wherever correctness is executable or the tool audit decides it. Jev grades remaining semantic criteria as boolean questions. Preserve probabilities as diagnostics; the initial learning signal uses pass/fail. Non-parsable stylistic requirements may need a judge, but invalid machine-readable output must not be rescued by one. Graders receive no tools that can execute a candidate's embedded instructions.

## Offline protocol proposal

Freeze the following before collecting scored results. Counts bound an engineering pilot, not a population-level claim.

1. Author 48 small tasks in 12 task families, four related variants per family. Use sandboxed repository repairs or transformations with checkable outputs and an explanation grounded in the observed trace. Choose six criteria per task: three executable/auditable and three semantic. Keep entire families, shared initial repositories and paraphrases together. Assign four families each to development, calibration and final evaluation, giving 16 tasks per split. Freeze corpus rights, hashes, exact prompts, allowed tools, stopping limits and rubric applicability.
2. Generate `N = 4` independent rollouts for every task from one pinned policy, resetting the same initial state and constraints for each. Before grading, also capture four rollouts per final task from a second preselected policy checkpoint as a distribution-shift test. This gives 256 rollouts and 768 semantic criterion labels. Policy identity is hidden from graders and annotators. Preserve duplicates, failed attempts, timeouts and action histories; never choose only successful or diverse-looking rollouts.
3. Two independent human reviewers label semantic criteria using the frozen rubric and evidence, blind to grader outputs. Resolve disagreement through recorded adjudication. Retain individual labels, agreement and ambiguous cases; revise an ambiguous criterion only on development data. Deterministic checks remain executable reference evidence. Final test labels and traces never enter rubric/GEPA search, grader calibration or checkpoint selection. Inspect subgroup leakage by task family, not just exact prompt equality.
4. Compare deterministic-only rewards, deterministic-plus-Jev, deterministic-plus-one-pinned-generative-LLM and the adjudicated reference reward on exactly the same rollouts. The deterministic-only control has a deliberately reduced objective and is labeled accordingly. The LLM receives the same rubric, evidence and output fields, using an efficient multi-criterion request. It returns bounded pass probabilities and labels; self-reported probabilities receive no presumption of calibration. Primary Jev passes use `p(pass) >= 0.5`. Any fitted calibration or alternative threshold is a separately named condition selected on calibration only and locked before final labels open.
5. Freeze a diagnostic manifest for repeated unchanged judgments, criterion ordering, singleton/native-batch equivalence, long traces, near-tied groups, adversarial grade instructions, forged “tests passed” text and a destructive-then-restored action. Use structured audit evidence to expose forged claims. Bound the two model-grader arms to 2,500 logical semantic checks including diagnostics, with at most one retry for eligible transport failures. Primary comparisons require 1,536 such checks before diagnostics. Record all attempts; never retry a completed unfavorable or malformed judgment to obtain a better answer.

## Reward and advantage rules

Code computes `r_i = sum(w_m * pass_im) / sum(w_m)` with nonnegative frozen weights. Applicability is established before grading; a runtime error cannot shrink the denominator. Any deterministic hard-failure override is explicit and shared by both grader arms. The proposed initial normalization uses population standard deviation, epsilon `1e-6`, and zero advantages for a complete all-equal group. Pin that choice and the trainer's actual implementation before a pilot.

An unavailable or unsupported criterion leaves the reward unknown. Exclude its entire group from an update under a preregistered recovery policy, retain the group in attempted coverage, and use matched complete groups for reward/advantage comparisons. Report excluded groups by family and failure reason. Do not award zero, partial credit or a silently repaired reward. Distinguish valid task failure from sandbox or grader infrastructure failure. Reject nonfinite rewards and advantage values.

Measure per-criterion confusion matrices, balanced accuracy, Brier/log loss, reliability-bin counts and annotation agreement. Then measure aggregate reward error, pairwise ranking agreement with ties, best-of-four selection regret, advantage error and sign disagreements against the adjudicated reference. Report zero-variance groups and near-zero reference advantages separately. Use paired task-family intervals; neither criteria nor four rollouts are independent task samples. Repeat and batch variability are additional effects, not more test cases.

## Gate to a separate training pilot

Offline results must first satisfy preregistered bounds on critical false passes, reward ranking, advantage disagreement and complete-group coverage, with uncertainty. Set these numeric bounds on development/calibration evidence before final evaluation. A low cost alone cannot close this gate. Keep unsupported and negative findings publishable even when training should not proceed.

If the gate passes, freeze a separate small policy-training protocol with three seeds, an unchanged-policy reference, deterministic-only and both semantic-grader arms. Match starting policy, tools, task distribution, rollout/update budget, optimizer, clipping/KL and token masking. Keep rubric, judge and weights fixed. Generate fresh on-policy rollouts after each update; cached offline trajectories alone are not an on-policy GRPO run. Reserve new task families for policy development and final testing so the already inspected offline final set cannot become a fresh training holdout.

Select checkpoints only on policy-development tasks. At fixed update checkpoints, compare optimized reward with executable task outcomes and blinded human or stronger independent judging. Predefine a bounded longer-optimization stress arm and stop criteria for rising grader reward with falling independent quality, policy-induced prompt injection, critical violations or loss of coverage. Include the second rollout policy and newly trained policies in grader-shift analysis. A stronger judge is a comparator, not unquestioned ground truth. Never use the optimized Jev reward as the only final evaluator.

## Accounting and publication

Freeze monetary, token, concurrency, environment-time and GPU limits. Pin each grader's actual identity and configuration; routing must not silently replace an unavailable judge. Reject oversized evidence with an explicit coverage reason instead of truncating it. Report generation, sandbox, deterministic checks, semantic grading, batching/serialization, retries, cache lookup and optimizer costs. Show actual usage and unknown charges, cache keys/hits, full group-ready latency and later training-step latency. Match information, budget and batching opportunities across graders. Offline measured savings apply only to grading; hypothetical total-loop savings remain labeled scenarios. No exponential speedup or savings claim follows from `N × M` checks.

Publish the protocol, complete coverage ledger, human-label procedure, task/rollout manifests, criterion outputs, deterministic evidence, independent recomputation and a usable recorded example. The scene needs keyboard/touch support, mobile layout, dark mode, reduced motion, failure states and versioned export before catalog inclusion. Preserve existing JudgeBench, RewardBench, local-model and linear-policy results with their original scopes. This ticket adds no training run or public performance claim; implementation tasks belong in the separate root-owned checklist.
