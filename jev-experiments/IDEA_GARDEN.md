# Twenty directions after the first experiments

The most interesting opportunity is a different division of labor. A writer proposes possibilities; many bounded questions inspect them; code preserves constraints and combines results; a human decides which outcomes matter. The pilots show this is practical. They also show why a cheap judgment should remain inspectable: the writer selector missed good candidates, the vision bridge lost evidence, and training on a reward did not make the reward an independent measure of success.

These are proposed experiments, not measured capabilities. Each has a small first test and an external measure that could disprove the idea.

| Direction | Model composition and first experiment | Evidence that would make it useful |
| --- | --- | --- |
| 1. Semantic change notifications | Jev judges whether a document edit invalidates each of 50 named assumptions. A reasoning model investigates only changed assumptions. Compare with diff and embedding triggers. | Fewer missed consequential changes at a fixed number of interruptions. |
| 2. An agent's evidence clerk | Attach source IDs, timestamps, contradiction flags, and completion claims to every tool result. Jev scores task relevance; code preserves mandatory errors and provenance. | Agent completion accuracy at 25%, 50%, and 75% of its original context tokens. Count lost facts separately. |
| 3. Counterfactual task router | Run a sampled request on a cheap local model, a fast hosted writer, and a reasoning model. Learn whether Jev can predict which extra compute changes the outcome. | Correct-task rate per dollar and p95 latency, compared with a fixed model and simple routing rules. |
| 4. A verifier that requests evidence | Ask whether each claimed step has supporting artifacts. If uncertain, request one targeted tool call rather than ask a larger model to reread the whole trace. | False acceptance of incomplete work and extra tool calls per genuinely completed task. |
| 5. Reward-model disagreement mining | Jev scores compatibility, constraint satisfaction, and style separately. Train a small policy, then search for outputs that increase reward while failing executable checks. | Frequency of reward exploits and improvement after adding counterexamples. This directly extends the beverage policy. |
| 6. Labeling with an abstention budget | Batch labels, then send uncertain or mutually inconsistent cases to a human. Compare entropy, disagreement, and random acquisition. | Held-out accuracy per human minute, not just agreement with Jev. Our first uncertainty run did not beat random. |
| 7. A personal taste model | Collect explicit human pairwise preferences for logos or short melodies. Jev supplies features; a small local model learns the person's deviations. | Blinded human preference on unseen prompts. Generic Jev reward must not be used as its own success metric. |
| 8. Semantic musical conducting | A sequencer keeps tempo and harmony. Jev chooses phrase tension, density, instrument entry, and resolution based on a story or game state. | Timing stability, harmonic violations, and listener ratings against a deterministic procedural baseline. |
| 9. A spatial instrument for drawings | Divide a canvas into regions and ask simultaneous questions about color, occupancy, direction, and edge continuity. Render in code, then ask a vision model where the drawing fails the brief. | Topology and object-count checks plus blinded preference. Compare independent pixels with hierarchical regions at equal cost. |
| 10. Interfaces that clarify | A schema enumerates supported workflows. Jev selects a layout and identifies the single missing preference that most changes the next step. | Task completion time, clarification count, and incorrect confirmations on ambiguous requests. Extend the beverage journey into a real usability study. |
| 11. Accessibility as an explicit preference | Ask the user for navigation and presentation preferences, then let Jev select from accessible components. Preserve keyboard order in code. | Keyboard and screen-reader task success. Never infer disability or silently override stated preferences. |
| 12. Vision with evidence-preserving crops | A vision model produces captions for the whole image and numbered regions. Jev routes a question to a region or asks for another crop. | Correct localization and answer accuracy versus a single lossy caption. Our screenshot failure is the starting case. |
| 13. Search as a question lattice | Cheap lexical retrieval provides 100 candidates. Jev checks answerability, freshness, and direct evidence independently. A writer answers only from selected spans. | Citation correctness and retrieval recall, including questions whose answer is absent. |
| 14. Micro-agents as typed functions | Each micro-agent has one input schema, one bounded judgment, and one return schema. Compose a planner, evidence selector, and completion checker through an explicit state machine. | End-task success and recoverability after injected failures, compared with one long model prompt. |
| 15. A living simulation | Jev maps free-form intentions into legal weather, ecology, and character actions. Simulation code handles conservation rules and time. Batch one decision per character per turn. | Diversity of behavior without illegal transitions; compare scripted characters and repeated-state caching. |
| 16. Cheap semantic test generation | A writer generates tricky cases; Jev classifies the kind of mistake each targets; executable rules discard trivial or invalid cases. GEPA revises the judge's contract. | New bugs found in an untouched test set, not how often a model agrees with generated labels. |
| 17. Compiler-style semantic adapters | Extend the current typed adapters with named rubrics, reusable question IDs, distribution-preserving composition, and schema-version hashes. | Identical decoded values and validation behavior across languages, plus explicit failure on unsupported output domains. |
| 18. Local decision model with a hosted fallback | Expand the SmolLM2 pilot with genuine ordinal middle labels, negatives, and multiple domains. Route uncertain cases to Jev and record the correction. | Out-of-domain accuracy, calibration, hosted-call reduction, and forgetting after each update. Keep a locked test set. |
| 19. Decision caching with drift detection | Cache exact judgments first, then test semantic cache keys. Recheck a random fraction and invalidate when the underlying document, question contract, or model changes. | Hit rate and stale-decision rate. Exact caching already made the navigation comparison practical; approximate caching needs a separate experiment. |
| 20. Information-value scheduling | Estimate whether another model call, a tool call, or a user clarification is most likely to resolve the current uncertainty. Let code enforce a strict latency budget. | More completed tasks within a fixed wall-clock budget than always asking the strongest model. |

## Where I would go deeper first

I would start with evidence-preserving context reduction, counterfactual routing, and the local-model fallback. Their value can be measured without a subjective judge, and the output fits Jev's bounded API. The creative path I find most promising is the semantic conductor: it gives the model expressive control while deterministic audio code handles the timing that a network request cannot guarantee.

For training, the next experiment should diagnose the unchanged yes/no performance before scaling the recipe. Add balanced, independently constructed negatives, genuine middle-level score labels, and an out-of-domain holdout. Compare the small decision model with a trained linear baseline and hosted Jev on identical questions. More data and more steps are hypotheses to test, not guaranteed improvements.

For GEPA, jointly optimizing retrieval, individual question wording, and the host's decision thresholds is more ambitious than rewriting one prompt. Freeze the whole workflow before opening the test set. A workflow that raises a model's own reward but makes users slower or loses evidence has failed the experiment.
