# Live transport resume

The interrupted pass already added a per-thread `network_namespace()` helper, a caller PID/netns guard, HTTP CONNECT proxy handling, sanitized SQLite/stderr errors, and a shared generation deadline. It also preserved the first upstream error when the harness pipe closed. Those pieces remain. This resume changes five source/test files, with the incremental diff in [changes.patch](changes.patch). No commit or PR was created.

The missing piece was execution placement. A guard can reject a jailed caller but cannot give its upstream call egress. `OpenAITransport` now eagerly starts an `openai-egress` thread during trusted campaign setup, before any jail launch. DNS, socket creation, proxy CONNECT, TLS, and both HTTP endpoints execute there. The worker checks its PID and its own `/proc/thread-self/ns/net` against the setup context. The gateway-serving thread can remain in its confined namespace; no `setns` operation grants it egress. SQLite audit writes remain on the serialized caller side.

The regression confirms this failure mechanism, not the historical incident's exact cause. The checked-in launch path confines child processes with bubblewrap and does not itself call `setns` in the parent. A read-only [audit of the existing local run](prior-run-audit.json) found 31 paid-dispatch records, all with response references, and no diagnostics table in any transport database. It contains no retained thread-level namespace observation or underlying exception from the reported stall. Podman inspection here failed because the environment denies access to its local socket at `127.0.0.1:54307`, so no Linux qualification or paid proof was run in this session. A successful bare urllib GET alone cannot establish the failing thread's namespace or the POST transport's proxy route.

Candidate and harness confinement is unchanged. Deno permissions restrict fixture processes; the Linux jail provides child-only `--unshare-net`, cleared environment, dropped capabilities, seccomp and cgroup limits. Native OpenCode uses the inherited gateway pipe. Child launches close unrelated file descriptors, and provider credentials are never placed in their environment or launch payload. The fixture escape test now runs for opencode, codex and claude-code. Native Codex/Claude remain unqualified and fail closed; the supported live native path is OpenCode. Linux candidate/harness network, file and namespace denial tests remain part of verification. The new Linux test creates a different real network namespace in only the dispatching thread and checks that upstream sockets retain the original namespace while the caller stays confined.

Errors are written with `synchronous=FULL` to each run's `transport/<role>/transport.sqlite`, in `diagnostics.detail`, and immediately emitted as JSON on stderr. Fields include exception type and sanitized message, endpoint, phase, errno, HTTP status, direct/proxy route, elapsed time, deadline/caps, owner and caller netns, and upstream thread/netns. API keys, request strings and proxy credentials are redacted. Error bodies are not read; malformed HTTP status-line bytes are suppressed. The prior [diagnostic viewer](../live-gateway-transport-20260910/show_transport_errors.py) can read these databases.

The [deadline module](../../src/strive/vnext/harness/deadline.py) now defines a 10-second connect cap and 60-second connected-call cap. Counting and generation share the earlier of the gateway deadline and the contract wall budget, leaving one second for harness return. Caller waits are bounded as well as socket operations, covering blocked DNS and slow response trickles. A late connect is closed before HTTP send; cancellation shuts down connected sockets. The transport refuses further work after an unresponsive worker, and close waits at most one second. Python cannot terminate a blocked resolver thread portably, so an abandoned worker is a daemon and never writes receipts or diagnostics after abandonment.

Ambiguous execution still means no retry, retain reservation, and suspend through existing recovery. An additional durable attempts index prevents redispatch even when the counting endpoint fails before a paid call is recorded. Frozen broker, ledger, supervisor and verifier code was not changed.
