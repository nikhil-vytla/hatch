Strive is a self-evolving agent harness built in two phases: a working vertical slice of the gated loop — execute → observe → evaluate → diagnose → propose → validate → accept/reject → retain — over executable strategy code in isolated subprocesses, followed by a deep research pass over six external systems (Flex/GEPA, [prime-agent](https://github.com/primeintellect-ai/prime-agent), the Continual Harness paper arXiv:2605.09998, [exoharness/exo](https://github.com/exoharness/exo), Recursive Language Models, NVIDIA's NOOA) with repos pinned at exact commit SHAs and code-level inspection. The central finding: the researched systems occupy complementary parts of the design space — GEPA validates candidates rigorously (persisting logs, checkpoints, and candidate programs) but lacks deployment-level activation and rollback semantics, while prime-agent, Continual Harness, and exo persist and self-modify richly without a pre-activation comparative behavioral promotion gate, often for defensible reasons; whether combining these mechanisms improves long-run performance is the hypothesis strive exists to test. That evidence drove 14 architectural decisions, a trusted-kernel platform design supporting both offline and bounded online evolution, and a 7-stage roadmap whose optional final stage co-evolves harness behavior and model weights. The prototype passes 23 offline tests with strict typing and ships a committed demo ledger showing acceptance, restart persistence, rollback, and branching lineage.

- Validated slice: seed strategy fails negative-integer cases; weakness diagnosed from trace evidence alone, patched, validated in a fresh sandbox, accepted 0.571 → 1.000 with zero regressions, journaled with full lineage.
- Key research evidence: the Continual Harness paper documents an inherited-usage collapse to 6.4% (evidence for reuse/inheritance protection) and an 842-repetition stall (evidence for loud schema rejection and trusted stall detection) — specific mechanisms strive adopts regardless of the broader gated-vs-ungated question, which remains an open hypothesis.
- Architecture invariants: trust boundaries by mechanism not policy, all metrics computed trusted-side, failure-as-score, append-only history, model I/O journaled for offline replay.
- Phase 3 executed the full hardening queue: versioned typed contracts with one strict shared codec, content-addressed artifacts, atomic promotion with journaled rollback, task-owned scoring across visible/held-out/regression/adversarial splits with mechanical holdout isolation, trusted budgets and stall freezing, pluggable named+versioned acceptance policies including expiring provisional activations, and a machine-readable CLI (run/inspect/compare/lineage/replay/promote/rollback).
- Phase 4 added the model-backed offline evolution loop (typed `Proposer` protocol, structured proposal schema with strict rejection classification, journaled model I/O with content-addressed prompts/completions, stale-proposal protection, a second task whose non-planted weakness the registry provably cannot fix); phase 4.5 then corrected it for precision: task-scoped ledgers, enforced token/cost/output budgets with defined zero semantics, an audit holdout excluded from selection, provisional activation refused for executable code, --unsafe-model-code acknowledgement for real models, execution-and-decision replay named honestly, and the offline "model" documented as a scripted proposal fixture (pipeline proof, not model reasoning); a final pass added loud legacy-ledger detection with a preserving `migrate-legacy` command, a shared task-binding guard with fingerprint-drift acknowledgement, exact token/cost budget semantics (output caps, journaled overrun rejection, fail-closed cost), precise trust-boundary language, and mandatory trace-evidence citation — 134 offline tests.
- Stage 3A settled the composite-evolution contracts design-first: six ADRs (revisions with typed per-surface deltas, artifact scopes with shadowing, task-spec/dataset separation, stable evidence/selection envelopes, gated evolution-algorithm services, storage backends + a migration registry) with experimental round-trip-tested spike contracts — 149 offline tests, live loop untouched.
- Stage 3B landed dual-write revision storage: the frozen core wire types in their permanent module, deterministic field-preserving generation→revision mirrors (decision evidence via CAS provenance), checkable/repairable parity, and a sequential migration registry (legacy ledger + revision backfill) — 176 offline tests; generation-native records stay authoritative.
- Stage 3B.1 hardened the derived side and proved subject-specific shadow-read parity: migration intents pin the exact canonical source prefix under one operation-level lock with prefix-scoped completion, parity verifies the full artifact closure (missing derived objects repairable, corrupt ones fail closed), `parity --rebuild` quarantines a corrupt or stage-3B-era mirror journal and atomically installs a rebuild from canonical history, each concrete generation-native read is paired at its point of use with the revision-derived read (divergences deduplicated as durable interventions, derived corruption degrading to unavailable — never failing a committed canonical operation), every execution pins a per-subject ResolvedHarnessManifest naming the baseline revision at a tamper-evident journal head, and `strive shadow` reports coverage with a cutover gate demanding complete parity + zero divergences + declared minimum coverage — 207 offline tests; revisions still do not control behavior.
- Stage 3B.2 centralized every operation's reads behind one boundary (`StateReader`) with coherent per-operation snapshots at tamper-evident heads and stale-head-refusing mutations, made evaluated subjects honest (immutable unactivated candidate-overlay revisions with native provenance; per-execution ExecutionRecords separating the base resolved harness from the evaluated subject), replaced all revision-read validation with one parity-grade VerifiedRevisionSnapshot, and added a reversible revision-read canary: durable journaled modes (native default / shadow / revision-canary), a locked+fsynced evidence journal with burn-in epochs and finally-recorded per-check outcomes, eligibility demanding complete parity + zero divergences + minimum per-subject samples + all behavioral paths observed, a durable circuit breaker on unavailable/divergent derived state, and an immediate kill switch. A correction pass then made the snapshot genuinely coherent (canonical bytes+entries read once, mirror paired via read-recheck), the control fail-closed (atomic repair breaker+epoch reset, head-checked transitions, a journal-independent force-native override), candidate identity exact (validated unactivated overlay revisions with retention linked back and verified content-identical), the evidence tamper-evident (task-bound, crash-framed, hash-chained reader journal detecting deletion/reordering/forgery), and the threat model explicit (canary refused for unsafe model-generated code) — 232 offline tests; strive runs a revision-derived execution/read canary from a coherent snapshot with tamper-evident current-epoch evidence and fail-closed control, while activation remains generation-native.
- Stage 3B.3 added the canonical native-revision lifecycle (`strive.lifecycle`, a task-scoped crash-framed hash-chained journal built on the shared `strive.framing` extracted from the reader): it owns native composite revisions while the generation ledger and mirror become explicitly-derived compatibility state. The candidate overlay created and validated before evaluation is retained unchanged for both rejected and accepted candidates with evidence linked by CAS ref, and on acceptance the same revision is activated — so the evaluated, retained, and activated revision ids are identical. Active state materializes from the complete ScopeManifest (lossless multi-surface, demonstrated with a code+prompt fixture that survives retain/activate/restart/rollback); retention and activation validate the whole revision, manifest closure, parent head, and artifact hashes; whole-revision rollback re-activates the prior known-good revision; invalid composite activation opens a durable breaker with no lossy fallback — 250 offline tests; prompt/policy evolution remains unimplemented, and activation of behavior remains generation-native.
- A correction pass then hardened the lifecycle before merge: migrations preserve upgrade history exactly (0003 backfills identities plus the full activation replay so the actual active revision survives; 0004 migrates the PR#43 reader journal byte-preservingly, refusing ambiguity), framed journals refuse appends over unverified regions with durable quarantine+truncate recovery, activation became one recoverable cross-journal operation (identity and evidence persist before served behavior changes; crash points abandon/resume/revert with a breaker; rollback drives both journals and parity is exposed), composite state is replayed against the parent manifest (stale before-states, undeclared changes, and dropped surfaces fail closed), identity was separated from per-assessment evidence with an accepted-selection gate and durable trusted overrides, and lifecycle authority is refused for unsafe model-generated code under the stated same-UID threat model — 257 offline tests.
- Stage 3C.1 ran the first empirically evaluated prompt-surface composite evolution experiment on that lifecycle: the proposal template became an operational evolvable surface (resolved from the active revision's manifest with a versioned validator, journaled per model request, restored by restart and rollback), proposals gained bounded prompt updates that build one exact prompt+code candidate revision before evaluation, and a matched five-arm experiment with a deterministic prompt-sensitive adapter proved the causal wiring — the incumbent prompt measurably fails the proposer, the candidate prompt flips the outcome with everything else held equal, ablations isolate prompt vs code effects, and the composite passes the trusted gate and activates as one revision surviving restart and rollback; the fixture proves pipeline wiring, with real-model runs opt-in and honestly recorded rather than claimed. A pre-merge correction pass then made prompt evidence surface-specific: a trusted prompt-vs-prompt comparison (matched proposer trials, strict-dominance verdict) must pass before any prompt delta activates — otherwise the code-only sibling activates and the composite is retained as rejected evidence; the default template is pinned into lifecycle state (rollback restores the historical text, not the current build's), requests pin and re-check the prompt ref and lifecycle head across the slow model call, the hardened prompt@3 descriptor Formatter-validates templates and bounds rendered prompts before provider calls, proposals carry generic typed surface updates, and the experiment gained a two-stage self-produced composite (the incumbent proposer writes the prompt that then writes the code, one exact revision id end to end) with a persisted manifest, unique run directories, and single-trial-labeled real-model runs — 271 offline tests; neither surface may piggyback on the other's evidence.
- Stage 3C.2A froze the evidence and selection envelopes on top of that lifecycle: dataset revisions with per-split content-addressed manifests (growth creates a new revision and a re-evaluation requirement, never a task-drift acknowledgement), evaluation manifests pinning everything an assessment ran under, role-bound validation bundles (task/prompt/constraint — flat metrics, per-case CAS artifacts) produced by a trusted validator registry resolved by exact name@version, and policy-neutral selection decisions with typed evidence roles and a closed disposition vocabulary where every disposition requires evidence. Activation is authorized only by complete current evidence for the exact revision and active baseline — missing roles, borrowed subjects, relabeled roles, stale datasets, unknown validator versions, corrupt artifacts, and failed or inconclusive hard constraints all fail closed — and cites the exact selection decision; pre-envelope history is linked to synthetic-but-lossless envelopes without rewriting a byte, replay recomputes bundle metrics, and `strive evidence` exposes the full readiness verdict — 288 offline tests; next is a budget-matched hill-climb versus GEPA-style Pareto-population experiment on these envelopes unchanged.
- A correction pass (3C.2A.1) then made those envelopes authoritative: evaluation manifests pin the exact task spec, dataset revision, resolved harness, and execution record by content address with verified fingerprints and agreement checks; the live mutation guard switched from case-inclusive fingerprints to task-spec drift, so growing the dataset passes the real guard unacknowledged and forces incumbent re-baselining; promotion demands each role's exact prescribed validator set one-to-one with results, a passed paired comparison with agreeing decoded artifacts (a wrong-but-noncrashing candidate cannot promote), matching objective specs, and verified execution provenance; migrated or inferred evidence is preserved for inspection, replay, and rollback but never authorizes a fresh promotion; budget constraints cover all seven metered dimensions with the meter's exact limit semantics; and dataset-revision creation became locked, expected-head checked, crash-safe, idempotent, and CAS-closure verified — 300 offline tests, with strive authorizing activation only from evidence whose task, dataset, harness state, validators, objectives, budgets, subject, and baseline all match the exact evaluation that produced the decision.
