# ADR-0021: `strive eval`, whether learning helps

Status: accepted, not built.

## Context

strive learns by proposing changes to memory and skills that a person
accepts. Nothing yet measures whether an accepted change helps. The
per-proposal replay check that tried to (ADR-0018, superseded) had no
power: at 3 runs a side, a change that does nothing passes "with more than
without" about a third of the time.

What the rest of the field does (NOTES, 2026-09-28):
- **Prime Agent** gates releases with an A/B run: 28 fixed, stratified
  tasks, one pinned model, a gold-patch oracle that must pass first, no
  retries, fail-closed thresholds. It never measures its own refinement.
- **exo** runs Harbor trials in order on one evolving agent, against plain
  control harnesses. It doesn't yet measure its learning step either.
- **Research** gives no clear answer:
  - Skills written before any trajectory scored −1.3 points; curated ones
    +16.2 (only +4.5 in software engineering), and Haiku 4.5 with skills
    beat Opus 4.5 without (SkillsBench, 2602.12670).
  - Four production memory systems lost to memory-off in 11 of 12 pairings
    (VibeMemBench, 2609.23570), though its targets were filtered on
    injection success.
  - A harness update's gain is non-monotonic in model strength: mid-tier
    models gain most; weak ones fail to load the artifact or don't follow
    it (2605.30621).
  - Naive in-context learning beat dedicated memory systems on CL-Bench's
    codebase-adaptation stream (2606.05661).

So the question to answer first is the plain one: **does strive with
learning on do better, over a sequence of related tasks, than the same
strive with learning frozen?**

## Decision

### The task suite: a synthetic project of task families

A family is one project quirk that recurs across surface variants: a
non-default test command, a required env var, a codegen step to rerun, an
in-house assert helper, a banned API with its replacement, a changelog
convention CI checks, a lockfile to update, error codes from a registry
file.
- **12 families:** 9 learnable; 2 generic bugs with no quirk (learning
  should do nothing, so a drop measures harm); 1 with conflicting
  conventions in two packages (tests over-generalizing).
- **Each family has 1 seed instance to learn from and 3 test instances.**
  Test instances use different files, names and error text, so memory helps
  only if it states the rule. Learned files are scanned for strings unique
  to test instances; a hit is leakage.
- **2 more calibration instances per family, used only for screening:** a
  family is kept only if the frozen arm passes at most 50% and the
  oracle-memory arm at least 70%, so the model doesn't already know it
  and does use memory. Scored instances are never used to select.
- **Each task has an oracle solution that must pass its check first.**
  Checks are the project's own tests and scripts; the agent and the learner
  never see the checker's source.

### The arms

Same pinned model (Claude Haiku 4.5), same task sequences:

| Arm | What it is | Sequences |
|---|---|---|
| F, frozen | No learning, no memory | 3 orderings |
| L, learning | After each task, the learner runs on that session; every proposal passing the static check is accepted | 3 orderings |
| O, oracle | A person-written ideal memory, present from the start: the upper bound | 2 repetitions |
| P, poison | L, with some seed sessions that pass for the wrong reason (a flaky check, a user asserting a false rule) | 1 ordering |
| Placebo | A same-length memory about an unrelated project: controls for "more context" | 1 repetition |

Orderings interleave families, always seed before tests. Each early family
is probed again at the end, to measure forgetting as memory grows.

### How it's scored

From artifacts only (exit codes, check results), never from what the agent
reports. Per task: pass, turns, cost, whether each learned file was loaded,
and whether it was followed.
- **Primary:** paired L − F on learnable test instances, with a cluster
  bootstrap over family × ordering; tasks within a family aren't
  independent.
- **Secondary:** McNemar on pooled pairs; a family-level sign test;
  Wilcoxon on turns.
- **Power:** with 81 pairs and the frozen arm near 30%, about 0.8–0.96 to
  detect a 30-point lift and about 0.4 for 15 points. This run detects
  large effects only, and says so.
- **Fail-closed:** a missing trial, a failed oracle or a model change fails
  the run. No retries.

### Pre-registered hypotheses

- **H1:** L − F on learnable families ≥ 15 pp, with the cluster CI's lower
  bound above 0.
- **H2:** learning efficiency, (L − F)/(O − F), ≥ 0.5.
- **H3:** on generic families, L − F > −10 pp (learning does no harm).
- **H4:** P > F − 10 pp, and the conflicting family shows no
  cross-application.
- **H5:** turns in L ≤ 0.85 × turns in F.
- **H6:** O − placebo ≥ 20 pp (the content matters, not the length).

### What the result changes

- O − F under 15 pp: memory can't help this model here. Fix loading and
  following, or change the model, before touching the learner.
- O − F large but efficiency under 0.25: the learner is the bottleneck;
  simplify or rebuild the proposer.
- P or the generic families lose more than 10 pp: the judge must block,
  not advise.
- H1 and H2 pass: learning earns more investment, starting with a larger
  replication on strive's own history.

### Cost

About $33–52 on Haiku 4.5 for all arms and screening, at $0.05–0.08 a task
plus $0.02–0.03 a learner run. If screening shows more than $0.07 a task,
the placebo arm is dropped. A dry run prints the plan and its estimate.

### Where it lives

A script and a task suite under `eval/` (`scripts/eval/`), run by hand. It
reuses `strive run` directly or through `harbor/strive_agent.py`; a
`strive eval` command can come later if it earns one.

## Consequences

- Learning features wait on this. If the learning arm doesn't beat the
  frozen one, the learning loop is simplified further, not extended.
- It costs real money on every run, so each run has a budget and a dry run
  that prints the plan and its estimated cost.
- A negative result is a result: it goes in NOTES with its numbers.

## Settled

Budget up to about $50, model Claude Haiku 4.5, and a synthetic project
(2026-09-29). The design follows a review of how continual-learning,
agent-benchmark, memory, self-improvement, personalization, statistics and
safety researchers would judge it (NOTES).
