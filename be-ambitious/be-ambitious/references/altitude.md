# Altitude

Ask for the outcome, not the task. The question to keep asking is: what do you want to happen next? Then look for the goal behind that goal.

**Signals:**
- The work would normally need a meeting.
- The same request keeps coming back. "Fix this crash" is really "keep the app crash-free".

**Climbing, using a quarterly business review as the example:**
1. Give the model all the raw data. Ask what changed, why, and what to do about it.
2. Ask for the three most urgent decisions, with the case for and against each.
3. Ask it to design a better process than the quarterly deck for catching problems early. Have it check the process against the company's history, then run it alongside the deck for a quarter.

**Durable workflows:** altitude pays off once the model can keep going without someone prompting each step. That usually means changing your own setup. Give the model its inputs (crash reports), the mappings it needs (version → commit) and a way to verify its own fixes (machines on each OS).

**Limit:** fully open goals still work poorly. The ceiling rises with each model, so try one level higher than feels safe.
