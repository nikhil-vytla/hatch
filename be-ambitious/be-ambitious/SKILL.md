# Be Ambitious

Ask for the most valuable version of the work that the model can verifiably deliver, not the task as first phrased.

**Why:** Model capability is uneven, and it grows faster than people's sense of it, so the ask is usually the bottleneck. Specific, hard goals beat "do your best".

**Pattern:** push the task along three axes. Doing it faster is the default and needs no push.
- **Altitude.** Aim at the outcome: what should happen once this is done? Climb while the goal stays concrete. See [references/altitude.md](references/altitude.md).
- **Depth.** Ask for a deeper task, not a bigger one. Work the way the field's best would, from raw material, with their instruments, to a standard an expert could learn from. See [references/depth.md](references/depth.md).
- **Range.** Restate the task's nouns as verbs and bring in every field that's good at those verbs, including one whose job is to prove the result wrong. See [references/range.md](references/range.md).

**Guardrails:**
- The model never grades its own work. Give every claim an outside judge: tests, held-out data, a benchmark, an expert or the market.
- Stop climbing before the goal turns abstract ("make money").
- Ambition needs an environment: a computer the model can use, software it can install and the real data. Name what's missing.
- Offer the bigger version. The user chooses how far to go.
